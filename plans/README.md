- **Three separate tests asserted the buggy behaviour** rather than catching it: `accounts.test.ts` asserted `investmentHolding.deleteMany` *was* called, `assets.test.ts`/`liabilities.test.ts` asserted `delete` *was* called, and the net-worth report fixtures set only the Decimal column with the Float at `0`. A test written against current behaviour pins whatever that behaviour is, including the bug.
- **Mutation-check new regression tests.** Every new test in this batch was verified by reintroducing the bug and confirming the test fails. This is the step whose absence let plan 004 be recorded as complete.
- **Do not add a gate that cannot fail.** This repo had two: a release gate measuring 16% of the code while reporting 96%, and a pre-push hook git ignored. PR #148 stays open rather than merging E2E with `continue-on-error`, for the same reason.

## Findings considered and rejected

### From the 2026-07-27 audit

- **`/metrics` unauthenticated in Express**: real, but unreachable through the bundled stack — `nginx/prod.conf` has no `/metrics` location and `docker-compose.prod.yml` exposes no server port. Downgraded to a note on the metrics-cardinality finding rather than a standalone plan.
- **SSRF via `/api/v1/logos?domain=`**: not SSRF. `services/logoService.ts:95-121` interpolates the domain into the *path* of two hardcoded hosts (`logo.clearbit.com`, `icons.duckduckgo.com`); there is no attacker-controlled host. The real issue there is the endpoint being unauthenticated with unbounded `logoCache` growth — tracked below, not planned this round.
- **`lib/safeOutboundUrl.ts`**: audited and found sound (protocol allow-list, embedded-credential rejection, DNS-resolution-based private/reserved range blocking for both IPv4 and IPv6-mapped). No finding.
- **`NetWorthSnapshot` Decimal shadow reads** (`standard.ts:1119-1121`): the stale-shadow bug does not apply — snapshot rows are immutable history, so Float and Decimal cannot diverge. Explicitly excluded from plan 021.
